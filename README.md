# Terraform + Ansible flow: tutorial

Learn the full **Infrastructure as Code** flow on AWS:

1. **Terraform** creates the infrastructure (network, servers, SSH key)
2. Terraform **hands over** to Ansible by generating its inventory (IPs + SSH key) automatically
3. **Ansible** configures the servers (installs Nginx and deploys a web page)

Everything runs in **`us-east-1`**.

## The learning path

The tutorial has 3 levels, one per branch. Each level builds on the previous one.

| Level | Branch | Infrastructure (Terraform) | Configuration (Ansible) | What you learn |
|---|---|---|---|---|
| 1 | `single-instance` | VPC + 1 subnet + **1** EC2 instance | One playbook, static page | The basic flow: `terraform apply` → `ansible-playbook` |
| 2 | **`main`** (you are here) | VPC + 3 subnets (3 AZs) + **3** EC2 instances | One playbook + **Jinja template** + `host_vars` | `for_each`, multiple AZs, per-host variables and templating |
| 3 | `load-balancer` | Level 2 + **Application Load Balancer** | Same page, packaged as an **Ansible role** | Load balancing, target groups, Ansible roles, `group_vars` |

> 🎯 **The goal of this tutorial is level 2 (this branch).** Start with level 1 if you're new to Terraform/Ansible,
> and go for level 3 as a bonus once level 2 works.

To switch level:

```bash
git checkout single-instance   # level 1
git checkout main              # level 2
git checkout load-balancer     # level 3
```

⚠️ Always run `terraform destroy` **before** switching branches. Each level has different infrastructure, and you don't want to leave servers running (or lose track of them).

## Before you start

You need:
- [Terraform](https://developer.hashicorp.com/terraform/install) (>= 1.5)
- [Ansible](https://docs.ansible.com/ansible/latest/installation_guide/index.html)
- AWS credentials configured. Check with `aws sts get-caller-identity`.

Every level asks for a **`student_name`** (lowercase, short, no spaces, e.g. `maria`). Everyone shares the same AWS account,
so this name is put on your resources (VPC, SSH key…) to keep them separate from your classmates'.

## Level 2: 3 instances (this branch)

### What gets created

Terraform (`infra/`):
- A new VPC with 3 public subnets, one per availability zone (`us-east-1a`, `b`, `c`) + internet gateway + route table
- 3 EC2 instances (`a`, `b`, `c`), one per subnet, open on ports 22 (SSH) and 80 (HTTP)
- An SSH key pair. The private key is saved straight into `ansible/<student_name>-ssh-key.pem`
- `ansible/inventory.ini`, generated with the 3 public IPs, so Ansible is ready to go with no copy-pasting

Ansible (`ansible/`):
- `playbook.yml` installs Nginx on the 3 machines
- `templates/index.html.j2` is rendered **per machine**, using the `username` variable from `host_vars/<host>.yml`
  (`a` → Alberta, `b` → Bocahontas, `c` → Cocoon)

```
infra/                 -> Terraform code (run terraform here)
ansible/               -> Ansible code (run ansible here)
  ansible.cfg          -> points Ansible to inventory.ini and disables host key checking
  inventory.ini        -> generated by Terraform
  playbook.yml         -> installs Nginx and deploys the page
  templates/           -> Jinja template for index.html
  host_vars/           -> one file per machine (a.yml, b.yml, c.yml)
```

### 1. Create the infrastructure

```bash
cd infra
terraform init
terraform plan  -var student_name=yourname   # see what will be created
terraform apply -var student_name=yourname
```

When it finishes, Terraform prints the public IP of each instance. Have a look at `ansible/inventory.ini` too: Terraform wrote it.

### 2. Configure the machines with Ansible

Wait about a minute for the instances to boot, then:

```bash
cd ../ansible
ansible all -m ping            # check that Ansible can reach the 3 machines
ansible-playbook playbook.yml  # install Nginx and deploy the page on each one
```

### 3. Check the result

```bash
terraform -chdir=../infra output public_ip
curl http://<one_of_the_ips>
```

Each machine answers with its own page: "Hello from Alberta / Bocahontas / Cocoon's website!".

### 4. Clean up

```bash
cd ../infra
terraform destroy -var student_name=yourname
```

## Ideas to go further

- Change the `username` in `ansible/host_vars/b.yml`, re-run the playbook and see only machine `b` change.
- Edit `templates/index.html.j2` to also show the machine's IP (hint: `{{ ansible_host }}`).
- Run the playbook twice. The second time most tasks say `ok` instead of `changed`. That's **idempotency**.
- Go to level 3 (`load-balancer`) and put an ALB in front of the 3 machines.
